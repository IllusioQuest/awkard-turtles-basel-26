# Network map data (decision 0025 §7)

What the network engine exports for the live map, and the mock export you can build the map against
**today**. Scenario: the Swiss test network `config/network/switzerland-test.json` (33 sites, 9 cities;
see `config/network/README.md`).

## Where the files are

| What | Path | Status |
|---|---|---|
| Real export (per strategy) | `results/network/<scenario>/<strategy>/` (generated by the network engine, git-ignored) | coming from T-12 step 2 |
| **Mock export** (same format) | `data/derived/network/switzerland-test/mock-export/{B1,B2}/` | committed, rebuild with `python scripts/make_network_mock_export.py` |

`<strategy>` is one of `B0` (always on), `B1` (local greedy), `B2` (network greedy), `LP` (rolling
horizon). A static file server cannot list folders, so the map should try these four ids and keep the
ones whose `run.json` loads.

**The mock is not a result.** It has no tank, no scheduler, and Type 1 work spread naively, and its
summer moves only go to the nearest hotel or pool. Every mock `run.json` and `summary.json` carries
`"mock": true`, and the map must show a "mock data" banner when it does.

## Time axis

Hourly, **8,760 steps**, local time **Europe/Zurich**, 24 values per local day (as the Open-Meteo
files; DST days are not shifted). Hour index `i` = day `⌊i/24⌋`, hour of day `i mod 24`. The start
is given in `site-hours.json → timeAxis.start` (`"2025-01-01T00:00"`). All arrays use this index.

## Files

### `run.json`: what produced the run
| Field | Meaning |
|---|---|
| `mock` | `true` for the mock; absent or `false` for real runs |
| `scenario`, `strategy`, `strategyLabel` | e.g. `switzerland-test`, `B2`, `"B2 network greedy"` |
| `gitCommit` | commit of the code that produced the run (`null` in the mock) |
| `forecast` | `{label, sigma24, rho, seed}`. The label must say whether it is perfect foresight or a forecast with error |
| `fillRate` | Type 2 availability φ (1 = unlimited) |
| `type1Share` | Type 1 volume as a share of heat-led server-hours (scenario, decision 0025 §6) |
| `horizonHours` | LP planning horizon (`null` for greedy strategies) |
| `inputs` | `[{path, sha256}]` of every input file |

### `sites.json`: the sites
`{scenario, timezone, sites: [...]}`. Each site is exactly the site object from
`config/network/switzerland-test.json`:
- `id`, `name`, `kind` (`reference-house-case`, `residential-sfh`, `residential-mfh`, `hotel-spa`,
  `indoor-pool`), `canton` (2-letter code), `countryCode`.
- Numeric fields `latitudeDeg`, `longitudeDeg`, `serverCount`, `serverElectricKw`, `heatRecoveryShare`,
  `tankCapacityKwh`, `minimumLoadShare`, `electricityPriceChfPerKwh`, `heatValueChfPerKwh` (and
  `persons` or `floorAreaM2` where present) are objects, either `{value, unit, source}` or
  `{value, unit, synthetic: true, note}`. **Show synthetic values as such**, e.g. "position:
  synthetic" in a tooltip.
- `demand` (how demand was built), `type1` (residential sites only: share, deadline, server-hours per
  job), `placement` (country allowlist CH).

Positions are city centre plus up to about 1.5 km random offset (synthetic), so sites of one city
nearly overlap. Drawing them on a small ring around the city is honest.

### `site-hours.json`: hourly values per site
`{timeAxis: {start, hours, stepHours, timezone}, sites: {<siteId>: {<field>: [8760 numbers]}}}`.
Numbers are rounded to 3 decimals; whole numbers are written as integers.

| Field | Unit | Meaning |
|---|---|---|
| `demandKwh` | kWh per hour | heat demand (space + hot water) |
| `usedKwh` | kWh per hour | demand met by server heat (direct + from the tank) |
| `dumpedKwh` | kWh per hour | server heat nobody needed |
| `backupKwh` | kWh per hour | demand met by the backup heater |
| `tankKwh` | kWh | tank content at the end of the hour |
| `loadShare` | 0–1 | achieved load per server |
| `type1ServerHours` | server-hours | Type 1 (LLM batch) work run at this site in this hour, own and moved-in |
| `type2ServerHours` | server-hours | Type 2 (research simulation) filler run here |
| `missedServerHours` | server-hours | Type 1 work of this site's cohorts dropped at its due hour (counted at the origin) |

Identities that hold in every hour: `demandKwh = usedKwh + backupKwh`, and
`loadShare × serverCount = type1ServerHours + type2ServerHours`.

### `flows.json`: work moving between sites
`{columns: ["hour","fromSiteId","toSiteId","type","serverHours"], rows: [[...], ...]}`.

- One row = Type 1 work of origin `fromSiteId` run at `toSiteId` in hour `hour`.
- Moves are **simulated flows only**: no data or container really moves (decision 0025 §3).
- Draw them as arcs. Aggregate rows per day for a daily view.

### `summary.json`: key figures
`{strategy, mock?, network: {...}, sites: [...]}`.

| Field | Unit | Meaning |
|---|---|---|
| `network.coverage` | 0–1 | share of total heat demand met by server heat |
| `network.dumpedHeatKwh` | kWh/year | heat dumped |
| `network.utilisation` | 0–1 | server running hours ÷ (servers × 8,760) |
| `network.serverHours` | server-hours/year | all work run |
| `network.missedDeadlinePercent` | % | Type 1 missed deadlines. In the mock: % of Type 1 server-hours due; in real runs: % of jobs due (decision 0025 §5) |
| `network.movedServerHours` | server-hours/year | work moved between sites |
| `sites[]` | per site | `siteId`, `coverage`, `dumpedHeatKwh`, `serverHours`, `type1ServerHours`, `missedServerHours` |

## Mock figures (for orientation only)
